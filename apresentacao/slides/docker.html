A suíte num container

FROM mcr.microsoft.com/playwright:v1.65.0-noble

WORKDIR /app

COPY package.json package-lock.json ./

RUN npm ci

COPY . .

ENV CI=1

CMD ["npx", "playwright", "test"]

docker build -f Dockerfile.e2e -t tatu-e2e .

docker run --rm --init --ipc=host \

  --env-file .env \

  -v "$PWD/playwright-report:/app/playwright-report" \

  tatu-e2e

--ipc=host: o Chromium não fica sem memória.

--init: cuida dos processos filhos do navegador.

--env-file: as variáveis entram sem ir para a imagem.

-v: o relatório sai do container.

Java: mcr.microsoft.com/playwright/java, com JDK e Maven.

A tag da imagem é a versão do @playwright/test. Atualizou um, atualize o outro, ou o navegador não é encontrado.

A imagem oficial do Playwright já traz os navegadores e as bibliotecas do sistema, então o Dockerfile é curto: copia o package-lock, instala, copia o resto e roda. Instalar as dependências antes de copiar o código deixa essa camada em cache. Com CI igual a 1, o config liga retries e sobe os servidores do zero, e o webServer sobe o BFF de mentira e o ng serve dentro do container. No docker run: --ipc=host evita que o Chromium fique sem memória, --init cuida dos processos filhos, --env-file passa as variáveis sem gravá-las na imagem, e o volume traz o relatório para fora. O cuidado número um: a tag da imagem precisa ser a mesma versão do @playwright/test do package.json. Para Java existe a imagem playwright/java. O projeto tem o Dockerfile.e2e e um docker-compose com os dois modos.
