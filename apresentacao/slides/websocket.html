WebSocket: cotação ao vivo

// o teste é o servidor

await page.routeWebSocket('**/ws/cotacao', (ws) => {

  ws.send(JSON.stringify({ moeda: 'USD', valor: 5.6 }));

});

 

// o servidor cai: a tela reconecta?

await page.routeWebSocket('**/ws/cotacao', (ws) => {

  if (++conexoes === 1) ws.close({ code: 1011 });

  else ws.send(tique(5.7));

});

 

// servidor de verdade, mensagem alterada no meio

await page.routeWebSocket('**/ws/cotacao', (ws) => {

  const servidor = ws.connectToServer();

  servidor.onMessage((m) => ws.send(trocarValor(m, 9.99)));

});

1. routeWebSocket é o page.route do tempo real.

2. Sem servidor: a tela mostra o valor que o teste mandar, na hora.

3. Queda e reconexão: o cenário mais difícil de reproduzir à mão.

4. connectToServer: o servidor real responde e o teste mexe no meio.

Para MFEs com tempo real: cotação, chat, status de transação, notificações.

Telas em tempo real usam WebSocket, e o routeWebSocket faz por elas o que o page.route faz pelo HTTP. No primeiro uso, o teste é o servidor: a tela recebe exatamente o valor que o teste mandar, sem servidor rodando. No segundo, o teste derruba a conexão e confere que a tela avisa e reconecta sozinha, que é o cenário mais difícil de reproduzir à mão. No terceiro, connectToServer liga no servidor de verdade e o teste altera as mensagens no caminho. No exemplo, a página de cotação ao vivo recebe um valor por segundo do mock BFF. Os quatro cenários estão no 25-websocket.spec.ts.
