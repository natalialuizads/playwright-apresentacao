Dá para testar uma CLI? Dá

const r = await rodar(['scripts/vigia.mjs'], {

  cwd: testInfo.outputPath(), // pasta só deste teste

  env: { VIGIA_SENHA: 'errada' }, // cenário pela variável

});

 

expect(r.codigo).toBe(1);

expect(JSON.parse(r.stderr)).toMatchObject({ ok: false });

expect(existsSync(`${pasta}/vigia-falha.png`)).toBe(true);

1. Código de saída: 0 é sucesso, o resto é erro.

2. stdout: o resultado. Em JSON, fica fácil conferir.

3. stderr: a mensagem de erro.

4. Efeitos: arquivo criado, porta aberta, chamada feita.

CLI que sobe servidor: espere a porta no stdout e teste com request ou page.

Java: ProcessBuilder dentro do JUnit, com a mesma lógica.

O runner não exige navegador: paralelismo, timeout, retry, pasta temporária e relatório servem para qualquer programa. Exemplos em e2e/14-cli.spec.ts.

O Playwright Test é um runner genérico: o navegador é só uma fixture. Para uma CLI, você roda o programa com child_process e confere quatro coisas: o código de saída, o stdout, o stderr e os efeitos colaterais. Cada teste ganha uma pasta própria com testInfo.outputPath, então a CLI pode criar arquivos sem um teste atrapalhar o outro, e as variáveis de ambiente montam cada cenário. No exemplo, a CLI testada é o vigia: login certo sai com zero e imprime JSON; senha errada sai com um e guarda uma captura; lento demais sai com dois. Para uma CLI que sobe um servidor, o teste espera a mensagem de porta no stdout e então testa com a fixture request ou abre a interface com page. Em Java, o mesmo se faz com ProcessBuilder no JUnit.
