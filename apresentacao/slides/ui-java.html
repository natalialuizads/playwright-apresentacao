O mesmo login, agora em Java

@UsePlaywright

class LoginE2ETest {

  @Test

  void clienteEntraEVeOSaldo(Page page) {

    page.navigate("http://localhost:4200/login");

    page.getByLabel("CPF").fill("123.456.789-09");

    page.getByLabel("Senha").fill("segredo123");

    page.getByRole(AriaRole.BUTTON,

      new Page.GetByRoleOptions().setName("Entrar")).click();

 

    assertThat(page).hasURL(Pattern.compile("inicio"));

    assertThat(page.getByTestId("saldo")).isVisible();

  }

}

Do TypeScript para o Java

TS   page.goto(url)

Java page.navigate(url)

TS   await expect(l).toBeVisible()

Java assertThat(l).isVisible()

TS   { name: 'Entrar' }

Java .setName("Entrar")

TS   await l.click()

Java l.click()

Mesmo teste do slide de Angular, linha por linha. As diferenças são só de linguagem: opções viram objetos com setters, o expect vira assertThat e não existe await. Isso abre uma porta interessante: o time de backend pode escrever o teste de ponta a ponta do fluxo que passa pelo BFF dele. Para rodar em paralelo, habilite o paralelismo do JUnit no junit-platform.properties; cada teste ganha seu próprio context.
