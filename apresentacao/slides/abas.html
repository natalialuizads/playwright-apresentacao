Redirecionamento, nova aba e popup

// redirecionamento: o expect espera a navegação

await page.goto('/extrato');

await expect(page).toHaveURL(/\/login$/);

 

// nova aba ou popup (target="_blank", window.open)

const novaAba = page.waitForEvent('popup');

await page.getByRole('link', { name: 'Comprovante' }).click();

const comprovante = await novaAba;

await expect(comprovante.getByRole('heading')).toBeVisible();

 

// login em popup (loginPopup do MSAL): o mesmo padrão

const popup = page.waitForEvent('popup');

await page.getByRole('button', { name: 'Entrar' }).click();

await (await popup).waitForEvent('close');

1. Registre a espera antes do clique, senão o evento passa antes.

2. A aba nova é do mesmo contexto: já está logada.

3. Cada aba é uma page: teste nas duas, feche a que abriu.

4. Outra origem? Sem cy.origin: é só usar a page.

Qualquer aba do contexto: context.waitForEvent('page').

Três situações de navegação. Redirecionamento: rota protegida sem sessão vai para o login; o toHaveURL espera a navegação terminar, sem sleep. Nova aba ou popup: um link com target blank ou um window.open abre outra página; o page.waitForEvent popup devolve essa page, e você testa nela como em qualquer outra. A espera precisa ser registrada antes do clique, por isso a promise vem primeiro e o await depois. A aba nova é do mesmo contexto, então já está logada. O login em popup do MSAL segue o mesmo padrão: pega o popup, preenche e espera ele fechar. E se a aba é de outra origem, como o portal de um parceiro, não muda nada; no Cypress isso exigiria cy.origin. O exemplo roda no 17-storage-e-abas.spec.ts.
