Mock no Java: tela e serviço de terceiro

Na tela: o mesmo page.route

page.route("**/api/cotacao", route ->

  route.fulfill(new Route.FulfillOptions()

    .setStatus(200)

    .setContentType("application/json")

    .setBody("{\"valor\": 4.99}")));

 

entrar(page);

assertThat(page.getByText("Dólar hoje"))

  .containsText("4,99");

No back: WireMock no lugar do terceiro

@DynamicPropertySource

static void props(DynamicPropertyRegistry r) {

  r.add("cotacao.url", wiremock::baseUrl);

}

 

wiremock.stubFor(get(urlEqualTo(CAMINHO))

  .willReturn(okJson(json)

    .withFixedDelay(3_000)));

 

APIResponse r = api.get("/api/cotacao", comToken());

assertEquals(503, r.status());

No Java temos dois tipos de mock. À esquerda, o page.route da API Java, idêntico ao do TypeScript: serve para os testes de tela. À direita, o WireMock sobe um servidor falso no lugar do serviço de cotação, e o DynamicPropertySource aponta a aplicação para ele. Assim testamos o que o nosso BFF faz quando o terceiro demora três segundos: aqui, ele estoura o timeout de um segundo e devolve 503 em vez de travar. Tudo isso está em CotacaoWireMockIT e LoginUiIT no projeto tatu-api.
