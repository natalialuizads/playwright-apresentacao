Como limpar cenários

novoCliente: async ({ request }, use) => {

  const criadas: string[] = [];

 

  await use(async (dados) => { // o teste roda aqui

    const r = await request.post('/api/teste/clientes',

      { data: dados });

    const cliente = await r.json();

    criadas.push(cliente.token);

    return cliente;

  });

 

  for (const token of criadas) // roda mesmo se falhar

    await request.delete(`/api/teste/clientes/${token}`);

},

1. Navegador: nada a fazer. Cada teste ganha context novo, sem cookie nem storage.

2. Dado do teste: a fixture cria e apaga, depois do use().

3. Dado da suíte: projeto de teardown, que roda no fim de tudo.

4. Ambiente: reset do banco de teste no pipeline, antes da suíte.

projects: [{ name: 'setup', teardown: 'limpeza' },

  { name: 'limpeza', testMatch: /limpeza\.ts/ }]

A regra: cada teste cria o seu dado. Limpar é garantia, não dependência.

Limpeza em quatro camadas. O navegador já é limpo: cada teste ganha um context novo, sem cookie, sem localStorage, então não precisa de afterEach para deslogar. O dado que o teste cria no backend é responsabilidade da fixture: o código antes do use prepara, o código depois do use limpa, e ele roda mesmo quando o teste falha. É melhor que afterEach porque a limpeza fica junto da criação e só roda para quem usou. O que vale para a suíte inteira, como uma massa de dados criada uma vez, vai num projeto de teardown, ligado ao setup pela propriedade teardown. E o ambiente de teste é resetado pelo pipeline antes da suíte, nunca no meio. A regra que sustenta tudo: cada teste cria o próprio dado com valores únicos, então mesmo que uma limpeza falhe, nenhum outro teste quebra por isso.
