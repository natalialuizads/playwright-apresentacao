Apps com Azure AD, hoje Entra ID, usam o MSAL, e o login passa pela tela da Microsoft. O padrão é o mesmo do login reaproveitado: um projeto setup entra uma vez de verdade e salva o estado. Quatro cuidados. Um: use um usuário só de teste, sem MFA, com uma política de acesso condicional que dispense o segundo fator só para ele e só no ambiente de teste; isso se combina com o time de identidade. Dois: o MSAL guarda os tokens no sessionStorage por padrão, e o storageState não salva sessionStorage; então o setup grava os itens à parte e uma fixture restaura em todo teste, ou o build de teste usa cacheLocation localStorage. Três: credenciais vêm do cofre do CI. Quatro: o token expira, em geral em uma hora, então o setup roda a cada execução. E para não depender da Microsoft em todo teste, o app pode ter um modo de teste com um provedor de identidade falso; só um ou dois testes passam pelo Azure de verdade. O arquivo completo está em referencias/msal-azure-ad.setup.ts.
