Skill e MCP: o agente testa do jeito do time

.claude/skills/testes-e2e/SKILL.md: as regras da casa, lidas pelo agente quando o assunto é teste.

---

name: testes-e2e

description: Como escrever e consertar testes

  Playwright neste projeto.

---

1. Locators por papel e rótulo. Nunca CSS de layout.

2. Nunca waitForTimeout: espere com expect.

3. Dado pela API (novoCliente). Cada teste cria o seu.

4. Consertando: abra o trace antes de mexer.

5. Não afrouxe asserção nem use test.skip.

.mcp.json: dá ao agente um navegador para abrir o app e ler a tela.

{ "mcpServers": {

    "playwright": {

      "command": "npx",

      "args": ["@playwright/mcp@latest"] } } }

Juntos: o MCP mostra a tela, a skill diz como escrever o teste dela.

Playwright CLI: playwright-cli install --skills instala a skill oficial de automação.

Duas peças práticas para quem usa agentes de código. A skill é um arquivo Markdown no repositório com as regras do time: que locators usar, que fixtures existem, como criar dados, e o que nunca fazer ao consertar um teste, como afrouxar asserção ou pular o teste. O agente lê a skill quando a tarefa é sobre testes, e o que ele escreve sai no padrão da casa. O MCP dá ao agente as mãos: com o Playwright MCP configurado no .mcp.json, ele abre o app, navega e lê a árvore de acessibilidade, então escreve locators que existem de verdade. A Playwright CLI para agentes também instala uma skill oficial de automação. No tatu-web estão os três arquivos: a skill, o .mcp.json para o Claude Code e o mcp.json do VS Code.
