Remote fora do ar

Bloqueie o remoteEntry e confira o fallback do shell.

Contrato

O remote registra o elemento que o shell usa: customElements.get.

Componente de outro time

getByRole entra no Shadow DOM aberto, sem configuração.

BFF na borda

Mocke só as APIs do remote; o resto da página é real.

O cenário que tutorial nenhum cobre e que a gente vive. Com Module Federation ou Web Components, o shell depende de um remote publicado por outro time. Quatro testes valem ouro: o shell sobrevive quando o remote cai, mostrando um fallback em vez de uma tela branca; o remote cumpre o contrato, registrando o elemento que o shell espera; os locators entram no Shadow DOM do componente de outro time; e o BFF do remote é mockado na borda, então o teste não depende do ambiente dele. O arquivo 11-microfrontends.spec.ts do projeto de exemplo tem os quatro, com shell e remote simulados por page.route, e roda sem servidor nenhum.
