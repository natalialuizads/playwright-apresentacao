Java: Cucumber com Playwright Java.

Vale a pena quando o negócio lê ou escreve os cenários. Se só dev lê, é uma camada a mais.

Dá, e em português: o Gherkin aceita Funcionalidade, Cenário, Dado, Quando, Então e Esquema do Cenário com tabela de exemplos. O pacote playwright-bdd, da comunidade, transforma cada cenário num teste do Playwright, então você não perde paralelismo, trace nem relatório; cada frase é ligada a uma função de passo que recebe as mesmas fixtures dos outros testes. Em Java, o caminho é o Cucumber com o Playwright Java. O cuidado: BDD é uma ferramenta de conversa. Vale quando produto, negócio ou QA leem e escrevem os cenários. Se só desenvolvedores vão ler, os passos viram uma camada extra para manter, e um teste comum com test.step bem nomeado entrega a mesma legibilidade. O exemplo roda com npm run e2e:bdd.
