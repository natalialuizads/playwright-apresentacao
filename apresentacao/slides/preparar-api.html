Chamar a API antes e validar na tela? Sim

test('prepara pela API, confere na tela',

  async ({ page, novoCliente, entrarComo }) => {

  // Arrange: pela API, em milissegundos

  const bia = await novoCliente({ nome: 'Bia', saldo: 250.5,

    extrato: [{ descricao: 'Conta de luz', valor: -180 }] });

  await entrarComo(bia);

 

  // Act e Assert: pela tela, que é o que está em teste

  await page.goto('/inicio');

  await expect(page.getByTestId('saldo')).toMostrarReais(250.5);

  await page.getByRole('link', { name: 'Extrato' }).click();

  await expect(page.getByRole('row', { name: /Conta de luz/ }))

    .toMostrarReais(180);

});

1. Prepara pela API

cliente, saldo, lançamentos

2. Age pela tela

o fluxo que está em teste

3. Confere na tela, e no backend se importa

saldo caiu? lançamento existe?

A condição: o que está em teste vai pela tela. Só o resto vem pela API.

Sim, é boa prática, com uma condição. Tudo que não é o foco do teste deve ser preparado pela API: criar a cliente, colocar saldo, lançar uma conta no extrato. Pela tela, isso levaria segundos e quebraria por motivos que não têm nada a ver com o teste. O que está sendo testado vai pela tela, porque é a tela que está em teste. O contrário também vale: agir pela tela e conferir no backend, por exemplo enviar um Pix pela interface e checar pela API que o saldo caiu e o lançamento existe. E cenários de borda, como saldo zero, ficam triviais: é um campo na criação. Os três casos estão no 15-dados-e-limpeza.spec.ts.
