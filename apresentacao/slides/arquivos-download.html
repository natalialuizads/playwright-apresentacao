Download: baixar e conferir o que veio

const download = page.waitForEvent('download');

await page.getByRole('button', { name: 'Exportar CSV' }).click();

const arquivo = await download;

 

expect(arquivo.suggestedFilename()).toBe('extrato-tatu.csv');

const caminho = testInfo.outputPath(arquivo.suggestedFilename());

await arquivo.saveAs(caminho);

await testInfo.attach('extrato-tatu.csv', { path: caminho });

 

// confira o CONTEÚDO, não só se o arquivo existe

const linhas = (await readFile(caminho, 'utf8'))

  .replace(/^\uFEFF/, '').split('\r\n');

expect(linhas[0]).toBe('data;descricao;valor');

expect(linhas).toContain('2026-11-09;Mercado do bairro;-312,40');

1. Espere o evento antes do clique, como no popup.

2. saveAs na pasta do teste; anexe ao relatório para quem investigar.

3. Confira o conteúdo: cabeçalho, linhas, separador, decimal com vírgula.

4. Dado pela API: o arquivo segue a cliente criada no teste.

PDF: extraia o texto com uma biblioteca como pdf-parse e confira o que importa.

Download segue o padrão do popup: espere o evento download antes do clique. O objeto que volta tem o nome sugerido, o caminho temporário e o saveAs, que grava na pasta do teste; anexar o arquivo ao relatório ajuda quem for investigar uma falha. O erro mais comum é parar em o arquivo existe. O teste que vale confere o conteúdo: o cabeçalho, as linhas, o separador e a vírgula decimal. No exemplo, o extrato exportado vem com BOM no começo, um caractere invisível que faz o Excel abrir os acentos certo, e o teste precisa saber disso. Com a cliente criada pela API, o teste também confere que o arquivo segue os dados dela. Para PDF, o caminho é extrair o texto com uma biblioteca como pdf-parse e conferir o que importa, como o valor e a data.
