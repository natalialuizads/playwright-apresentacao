expect.poll repete a consulta até o SMS chegar, sem sleep. A referência evita pegar o código de outro teste rodando em paralelo.

Código de uso único aparece em login com MFA e em confirmação de transação. Desligar o MFA no ambiente de teste é uma saída, mas existem formas de testar o fluxo de verdade. Se o código vem por SMS ou e-mail, o ambiente de teste aponta o envio para uma caixa de teste: a API de sandbox do provedor de SMS, ou um servidor de e-mail de teste como o Mailpit. O teste consulta essa caixa pela API, sempre filtrando pela referência da transação ou pelo destinatário, para não pegar o código de outro teste rodando em paralelo. Se é um app autenticador, o teste guarda o segredo da conta de teste e gera o código na hora com uma biblioteca como otpauth. A terceira opção, um código fixo, só vale no ambiente de teste, só para usuários de teste, e precisa ser combinada com o time de segurança. No exemplo, a compra no cartão manda o código para a caixa de SMS do mock BFF, e o teste espera com expect.poll até ele chegar.
